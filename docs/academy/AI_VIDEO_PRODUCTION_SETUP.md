# AI Video Production Setup

## 1. Purpose

Define the external production workflow for CEO's OS Visual Academy videos using screen recording, editing, captions, and optional AI avatar/voice tools.

This document is planning only. No video, image, audio, avatar, voice, raw recording, or generated media file is stored in the repository.

## 2. Production Principles

- Use IberNova or other synthetic data only.
- Keep CEO's OS positioned as a Private Executive DSS.
- Preserve Human Review Required.
- Keep Board Review Draft wording.
- Do not claim board approval, certified PDF, autonomous AI, legal advice, investment advice, SOC2/ISO certification, certified compliance, or production AI provider traffic.
- Store media outside the repository.
- Review every asset before sharing externally.

## 3. Recommended Production Stack

| Need | Recommended tools | Notes |
|---|---|---|
| Step-by-step walkthrough capture | Guidde or Supademo | Best for click-by-click product education |
| Raw screen recording | Loom or OBS | Best for practical walkthroughs and rehearsals |
| Avatar/founder-style presenter | HeyGen or Synthesia | Use only after Fernando approval |
| Editing/captions/cover frames | Canva, CapCut, or Descript | Keep source files outside repo |
| Hosting | Vimeo, Loom, YouTube unlisted, private Drive, or controlled data room | Use access controls appropriate to audience |

## 4. Screen Recording Workflow

1. Run `VISUAL_CAPTURE_CHECKLIST.md`.
2. Run `VISUAL_QA_BEFORE_RECORDING.md`.
3. Follow `VIDEO_CHAPTER_CAPTURE_PLAN.md`.
4. Record chapters separately where possible.
5. Use `SCREENSHOT_SHOT_LIST.md` for still captures.
6. Keep raw recordings outside the repository.
7. Review against `VIDEO_TRUTHFULNESS_CHECKLIST.md`.

## 5. AI Avatar Workflow

1. Obtain Fernando's approval before any likeness, avatar, or AI-generated presenter is used.
2. Use only approved source image/voice material.
3. Use approved scripts only.
4. Do not upload real client data to avatar tools.
5. Do not imply the avatar is live, autonomous, legal counsel, investment advisor, auditor, or board authority.
6. Version and store outputs outside the repository.

## 6. AI Voice Workflow

- Use approved script text.
- Use synthetic or approved recorded voice only.
- Do not clone or imitate a voice without explicit approval.
- Review captions for claim drift.
- Disclose synthetic narration where required by platform, context, or policy.

## 7. Editing Workflow

1. Assemble intro, chapters, captions, and outro.
2. Add cover frame and title.
3. Remove pauses, failed clicks, wrong screens, and unsafe wording.
4. Add callouts only where they clarify DSS/human-review behavior.
5. Export draft externally.
6. Run approval checklist before release.

## 8. Subtitles / Captions

- Captions must match approved wording.
- Fix transcription errors that introduce unsafe claims.
- Do not caption "certified PDF" unless saying it is prohibited.
- Keep "Board Review Draft", "Human Review Required", and "synthetic data" wording intact.

## 9. Branding

- Use CEO's OS naming consistently.
- Keep tone sober, executive, and non-hype.
- Do not imply external certification.
- Do not use third-party logos unless rights and context are approved.

## 10. Truthfulness Review

Review for:

- DSS framing.
- Human review.
- Synthetic data labels.
- Missing data visibility.
- Export/PDF wording.
- AI runtime limits.
- Bridge/Heritage labels.

## 11. Approval Process

1. Producer draft.
2. Product truthfulness review.
3. Security/privacy review.
4. Founder/avatar approval if used.
5. Final release approval.
6. Version log updated.

## 12. Publishing Process

- Host externally.
- Use access level: internal draft, unlisted prospect, controlled pilot, or public.
- Track link owner and version.
- Archive or revoke outdated versions.

## 13. Storage Outside Repo

Do not store in repo:

- Raw recordings.
- Video exports.
- Screenshots.
- Audio files.
- Avatar files.
- Voice files.
- Editing project files.
- Cover images.

## 14. Links Policy

- Keep public/unlisted links versioned.
- Do not paste access tokens or private links into public docs.
- Use controlled folders/data rooms for pilot-specific materials.
- Revoke old links when content becomes inaccurate.
