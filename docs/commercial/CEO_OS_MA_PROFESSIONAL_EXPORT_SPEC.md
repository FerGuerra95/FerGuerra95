# CEO’s OS — M&A Professional Export Spec

## Estado

**Bloque:** Punto 5 — Exportación M&A profesional  
**Estado:** En desarrollo  
**Prioridad:** Alta  
**Módulo afectado:** M&A  
**Objetivo:** Convertir el módulo M&A en un producto capaz de generar un entregable profesional, exportable y defendible.

---

# 1. Objetivo del punto 5

El objetivo del Punto 5 es que CEO’s OS no solo muestre análisis M&A en pantalla, sino que pueda generar un informe profesional con calidad consultiva.

El informe debe poder usarse para:

- presentar una valoración,
- explicar una tesis de inversión,
- documentar supuestos,
- mostrar waterfall,
- mostrar buyer matching,
- preparar un CIM preliminar,
- entregar un resumen ejecutivo,
- dejar trazabilidad de inputs,
- servir como output comercial del producto.

---

# 2. Resultado esperado

Al cerrar este punto, el módulo M&A debe poder generar un informe exportable con esta estructura:

- Portada
- Disclaimer DSS
- Resumen ejecutivo
- Company Snapshot
- Transaction Overview
- Financial Inputs
- EBITDA Adjustments
- Valuation Range
- Enterprise Value
- Equity Value
- Waterfall
- Buyer Matching
- Investment Thesis
- Risks & Mitigants
- Preliminary CIM
- Human Review Notes
- Appendix

---

# 3. Enfoque correcto

La exportación debe empezar de forma simple y robusta.

## 3.1. Fase inicial

Exportación HTML imprimible.

Ventajas:

- menos dependencias,
- fácil de probar,
- compatible con navegador,
- permite imprimir como PDF,
- no rompe backend,
- no exige infraestructura extra,
- permite iterar diseño rápido.

## 3.2. Fase posterior

Exportación PDF automática.

Opciones futuras:

- Playwright server-side.
- Puppeteer.
- Servicio externo.
- Generación PDF backend.
- Exportación DOCX si se necesita para consultoría.

---

# 4. Regla estratégica

La exportación M&A debe reforzar el posicionamiento de CEO’s OS como Decision Support System.

No debe decir que la plataforma toma decisiones finales.

Debe decir que:

- estructura información,
- calcula escenarios,
- documenta supuestos,
- genera outputs,
- permite revisión humana,
- ayuda a preparar decisiones.

No debe decir que:

- sustituye al asesor,
- sustituye al comité,
- emite recomendación vinculante,
- certifica valor final,
- hace due diligence completa,
- presta asesoramiento financiero regulado.

---

La exportación debe poder activarse desde:

## 5.1. Opción principal

## 5.2. Opción secundaria

## 8.2. Disclaimer DSS

Texto recomendado en inglés:

This report has been generated by CEO’s OS as a decision-support output. It is intended to structure information, assumptions, analysis and preliminary conclusions for human review.

The report does not constitute legal, financial, tax, investment or regulatory advice. All outputs should be reviewed and validated by qualified professionals before making any binding decision.

Texto recomendado en español:

Este informe ha sido generado por CEO’s OS como output de soporte a la decisión. Su finalidad es estructurar información, supuestos, análisis y conclusiones preliminares para revisión humana.

El informe no constituye asesoramiento legal, financiero, fiscal, de inversión o regulatorio. Todos los resultados deben ser revisados y validados por profesionales cualificados antes de tomar cualquier decisión vinculante.

# 12. Cálculos mínimos

## Enterprise Value

EV = Adjusted EBITDA × Multiple

## Equity Value

Equity Value = Enterprise Value - Net Debt + Cash + Other Adjustments

## Rango de valoración

Conservative EV = Adjusted EBITDA × Conservative Multiple  
Base EV = Adjusted EBITDA × Base Multiple  
Upside EV = Adjusted EBITDA × Upside Multiple

# 13. Reglas de seguridad y arquitectura

## 13.1. No romper multi-tenancy

La exportación nunca debe permitir acceder a datos de otra organización.

Si los datos vienen del backend, deben venir ya filtrados por `organizationId`.

El frontend no debe decidir qué datos pertenecen a cada organización.

---

## 13.2. No exponer secretos

El informe no debe incluir:

- tokens,
- secrets,
- variables de entorno,
- IDs internos sensibles,
- datos de otros tenants,
- credenciales,
- claves.

---

## 13.3. No romper backend

La primera versión de exportación puede hacerse frontend-only.

No tocar backend hasta que sea necesario guardar:

- reportes,
- versiones,
- snapshots,
- audit trail,
- exports.

---

## 13.4. No introducir dependencias pesadas sin necesidad

Primera versión:

HTML exportable + print to PDF

No añadir todavía:

- Puppeteer,
- Playwright server-side,
- PDFKit,
- docx,
- integraciones externas.

---

# 14. Estados del informe

Estados recomendados:

- Draft
- Pending Review
- Reviewed
- Approved
- Final
- Archived

Uso:

- Draft: generado automáticamente.
- Pending Review: pendiente de validación humana.
- Reviewed: revisado.
- Approved: validado internamente.
- Final: entregable cerrado.
- Archived: histórico.
